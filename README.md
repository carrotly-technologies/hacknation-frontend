# hacknation-frontend

React + TypeScript + Vite frontend for HackNation. It talks to the NestJS API in
[hacknation-backend](https://github.com/carrotly-technologies/hacknation-backend).

## Setup

```bash
npm install
cp .env.example .env   # optional
```

| Variable             | Default | Description                                                                                       |
| -------------------- | ------- | ------------------------------------------------------------------------------------------------- |
| `VITE_API_URL`       | empty   | Backend base URL. Empty = same origin, via the dev proxy `/api` -> `:3000`                        |
| `VITE_DEMO_ACCOUNTS` | empty   | `false` hides the demo accounts (one-click sign-in) on `/logowanie`; anything else shows them     |

Both are read at build time (`npm run build`, Docker build args).

The Docker image also reads `CSP_CONNECT_SRC` at container start (default: the `VITE_API_URL` build arg): the API
address the Content-Security-Policy lets the app connect to (see Deploy).

## Run

Start the backend first (`npm run start:dev` in `hacknation-backend`, port 3000), then:

```bash
npm run dev       # http://localhost:5173
```

The app is **Kompas Kompetencji** (UI in Polish), a work tool for civil-service
supervisors and HR, built around the assessment file ("teczka oceny"):

- `/logowanie` — sign-in with login and password; the role (supervisor, HR, admin) comes from the account
  (demo accounts: backend README; below the form one card per demo account signs in with one click,
  list in `src/lib/demoAccounts.ts`, hidden with `VITE_DEMO_ACCOUNTS=false`).
  Above the form, „Zaloguj przez login.gov.pl” runs a **simulation** of the Węzeł Krajowy flow (backend README,
  „Sign-in through login.gov.pl”): `POST /api/auth/login-gov/start` → `/mock-login-gov` (public mock identity
  provider outside the app shell: a visible „Symulacja: to nie jest prawdziwy login.gov.pl” banner, no official logos,
  no password fields; step 1 method, step 2 demo person) → `/logowanie/login-gov?artifact=…&state=…`, which exchanges
  the one-time artifact for a token and opens the role's start page (errors: message on `/logowanie`). The `state` is
  kept in `sessionStorage` (`kompas.loginGovState`) to bind the return to the tab that started it. Hidden together with
  the demo accounts (`VITE_DEMO_ACCOUNTS=false`). The token sits in `sessionStorage` and goes with every API call
  (`Authorization: Bearer`); a 401 sends you back to sign-in. Routes and the menu depend on the role, and a
  route for another role redirects to your start page (`src/lib/useAuth.ts`, `src/shell/RequireAuth.tsx`);
- `/admin/uzytkownicy` — admin only: accounts and their roles;
- `/admin/dziennik` — admin only: the append-only event log „Dziennik zdarzeń” (`GET /api/admin/audit*`,
  `src/api/audit.ts`): date and time, who (name and role, or the assessed person via the link), action (Polish name
  from the API) with the names of the changed fields, resource, result; filters by person, action (also „Wszystkie
  akcje w ocenie”) and local date range, 50 entries per page; „Sprawdź integralność” shows the result of
  `GET /api/admin/audit/verify` (success, or the id of the first broken entry);

- `/zespol` — my team: a table of people (name and position, hire date, current assessment step, nearest deadline; overdue first); a row opens the employee profile;
- `/pracownik/:personId` — employee profile (`GET /api/people/:personId`, `src/api/people.ts`): name and position,
  the last completed assessment (signed / acknowledged dates), employee data, supervisor, assessment history with
  links to the sheets, and one button: „Kontynuuj ocenę okresową” / „Kontynuuj pierwszą ocenę” to the case at its
  current step, or „Rozpocznij…” (inactive for now) when there is no open case; the case file's „Powrót” leads here;
- `/teczka/:id/:stage` — the case file: stage rail (periodic and first-assessment paths), stage workspaces
  (OSP analysis, the "Formularz oceny" sheet wizard filled part by part — parts I, II, III, current part in `?czesc=`, also opened for the assessment period (no sub-step tiles; the old `/obserwacje` link redirects there, and the assessment talk starts in step 4), rubric assessment with system suggestion and supervisor
  decision, justification/IPRZ with formal check, "Ocena końcowa": process status, the link for the assessed person,
  "Pobierz PDF" / "Pobierz DOCX" of the filled periodic sheet generated by the API (`GET /api/cases/:id/sheet.pdf|docx`,
  `downloadSheet` in `src/api/cases.ts`; the file name comes from `Content-Disposition`) and "Drukuj");
- `/teczka/:id/arkusz` — official sheet preview (parts I/II/III); `?druk=1` opens the print dialog (the first
  assessment's only way to a PDF; periodic sheets download a PDF from the API);
- `/zapoznanie/:token` — public page for the assessed person (no sign-in, outside the app shell): the signed sheet
  read only, the notice and the "zapoznałem(-łam) się" confirmation (`GET/POST /api/ack/:token`). The supervisor
  generates the link in part II of the sheet wizard ("Zapoznanie ocenianego z oceną"); the full address is built from
  this app's origin (`window.location.origin` + `ackLink` from the API);
- `/deklaracja-dostepnosci` — public accessibility statement (no sign-in, outside the app shell), linked in the footer
  of every screen and on `/logowanie`; sections of the statement template (ustawa o dostępności cyfrowej), demo entity
  and contact data marked "(przykład)" in `src/lib/accessibilityStatement.ts`; the audit behind it: `docs/wcag.md`;
- `/prezentacja` — public project presentation (no sign-in, outside the app shell, not linked from the navigation):
  at most 10 slides on a 16:9 canvas scaled to the window (upright phones get a 9:16 layout); ←/→, space,
  PageUp/PageDown, Home/End, swipe and the dots change the slide, `#N` in the URL opens slide N, `F` toggles full
  screen. Printing gives one slide per 1920×1080 page; the exported deck is `docs/prezentacja.pdf` (see "Presentation");
- `/aktywnosc` — the team's view of the activity log (public, outside the app shell, not linked anywhere;
  hacknation-backend#75): a token form (the backend's `MONITOR_TOKEN`, kept in `sessionStorage` `kompas.monitorToken`;
  a wrong token or an unset one gives 404 and the form again), then the sessions (account login, IP, browser and system
  parsed from the User-Agent, first and last activity, pages / API calls / errors), filters by date, IP and account in
  the URL, refreshed every 10 s; `?sesja=<id>` shows one session as a timeline (time, screen or API call, method and
  path, status coloured for 4xx/5xx, duration), screens highlighted (`src/pages/ActivityPage.tsx`, `src/api/monitor.ts`).
  Every API call carries `X-Session-Id`, a random UUID per tab in `sessionStorage` `kompas.session`
  (`src/lib/activity.ts`), and every route change sends `POST /api/telemetry/pageview` in the background
  (`src/lib/usePageviews.ts`; never blocks or shows an error; `/aktywnosc` itself is not reported). The footer of the
  app shell, `/logowanie` and `/zapoznanie/:token` says „Aplikacja rejestruje aktywność w celach analitycznych.”;
- `/hr` — HR monitoring with counters, filters and (simulated) reminders; a row opens the case file read-only (`/teczka/:id`, fields and actions disabled for HR); `/baza-wiedzy` — assistant and its sources;
- "Asystent AI" — a floating button in the bottom right corner of every screen in the app shell (not on
  `/zapoznanie/:token` or the sheet print view) opens the chat in a popup (about 400×600 above the button; full screen
  below 600px; Esc closes). In the case file it knows the case and the stage (`useAssistantContext`; only `caseId` and
  `stageId` go to the API), and "Przygotuj pytania do rozmowy" in step 5 opens it with the question. The conversation
  stays in memory for the signed-in session (`src/assistant/AssistantProvider.tsx`), nothing is stored in the browser.
  Always on (without an LLM on the backend it answers extractively, with citations);
- `/ustawienia` — appearance settings for every role (gear icon in the top bar; on phones in "Menu"): theme
  system/light/dark, text size 100/125/150%, high contrast. Kept only in this browser (`localStorage`
  `kompas.prefs`, `src/lib/preferences.ts`) and applied before the first paint by a small script in `index.html`;
- `/ui` — design-system catalogue, `/wniosek-demo` — step-by-step form pattern, `/wiecej`, `/uslugi`
  (helper pages: they work under their addresses but are not linked from the navigation).

API contract: the route tables in the backend README. Submission docs (project description, use of AI,
architecture): `docs/zgloszenie/` in hacknation-backend. Data fetching uses TanStack
Query, routing react-router; design tokens live in `src/styles/tokens.css`,
components in `src/components/ui/`; see `docs/DESIGN.md`.

Without a backend you can use a dev-only mock (off by default, never bundled):

```bash
MOCK_API=1 npm run dev   # serves v1 + v2 /api/* (dev-mock-api.ts, dev-mock-v2.ts); any password, login a.cieslak-dyjecinska = HR, admin = ADMIN
```

## Accessibility tests

WCAG 2.1 AA status and the manual screen-reader script: [`docs/wcag.md`](docs/wcag.md). The automated part is
Playwright with `@axe-core/playwright` (`e2e/`, `playwright.config.ts`):

- `e2e/a11y.spec.ts`: axe-core (tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`) must find 0 violations on every main
  screen (sign-in, statement, acknowledgement, team, profile, every case stage and form part, sheet, knowledge base,
  settings, HR, admin users and event log) in the light, dark and high-contrast (light and dark) themes;
- `e2e/keyboard.spec.ts`: the assessment path from sign-in to the link for the assessed person with the keyboard only
  (skip link, visible focus on every stop, the sign dialog's focus trap, Esc and focus return, menus and the assistant).

They run against the **real backend with in-memory storage** (the demo seed; the tests reset it with
`POST /api/demo/reset`), simpler than keeping `dev-mock-api.ts` in step with the API. Playwright starts its own Vite
server on port 5179 with the `/api` proxy pointed at the backend.

```bash
npx playwright install chromium          # once
# backend: in hacknation-backend `npm run start:dev` (port 3000), then here:
npm run test:a11y
# or let Playwright start the backend from a clone, on another port:
BACKEND_DIR=../hacknation-backend A11Y_API_URL=http://localhost:3100 npm run test:a11y
```

| Variable        | Default                 | Description                                                         |
| --------------- | ----------------------- | ------------------------------------------------------------------- |
| `A11Y_API_URL`  | `http://localhost:3000` | Backend for the tests                                               |
| `BACKEND_DIR`   | empty                   | Path to a hacknation-backend clone: Playwright starts it (`npm run start`) |
| `A11Y_APP_PORT` | `5179`                  | Port of the Vite server started for the tests                       |
| `APP_URL`       | empty                   | Test an already running frontend instead (its `/api` must reach the same backend) |

## Presentation

`/prezentacja` (`src/pages/PresentationPage.tsx`, illustrations and device frames in `src/pages/presentation/`) uses
real screenshots of the app from `public/prezentacja/*.png` (demo seed only, fictional people) and SVG drawings.
Both scripts use Playwright (devDependency, Apache-2.0); install its Chromium once with `npx playwright install chromium`.

```bash
npm run presentation:pdf      # docs/prezentacja.pdf, one 1920×1080 page per slide; starts its own Vite server
                              # (APP_URL=http://localhost:5173 uses a running one); no backend needed
npm run presentation:screens  # retakes public/prezentacja/*.png (2×, each < 400 kB); needs the backend and
                              # `npm run dev` running (APP_URL, default http://localhost:5173); resets the demo data
```

Retake the screenshots when the screens they show change, then export the PDF again.

## Deploy

Production runs on Coolify (project **Hackathons**, environment `production`)
as the `hacknation-frontend` application, built from this repo's `Dockerfile`
(Vite build, then nginx serving `dist/` with an SPA fallback to `index.html`):

- URL: <https://hacknation.rabbithole.carrotly.tech>
- API: <https://api.hacknation.rabbithole.carrotly.tech>, passed as the
  `VITE_API_URL` build arg (set as a build-time variable in Coolify). It is
  baked into the bundle, so changing it needs a redeploy.
- Every push to `main` triggers a new deploy (GitHub App source, auto-deploy on).
- TLS (1.2+) terminates at the Coolify proxy; `nginx.conf` adds
  `Strict-Transport-Security: max-age=31536000; includeSubDomains` to every response (RODO, see
  hacknation-backend `docs/rodo/dpia.md`).
- Security headers (OWASP ASVS L2, checklist in hacknation-backend `docs/security/asvs-l2.md`): `nginx.conf` sends on
  every response a `Content-Security-Policy` without `unsafe-inline` (`script-src 'self'`, `style-src 'self'`,
  `connect-src 'self'` plus the API, `frame-ancestors 'none'`, `object-src 'none'`), `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin` and a `Permissions-Policy` that turns off
  camera, microphone and geolocation. No inline `<script>` or `<style>`: the theme script that runs before the first
  paint is `public/preferences-init.js`.
- `nginx.conf` is a template (`/etc/nginx/templates/`): at container start nginx fills `${CSP_CONNECT_SRC}`, the API
  address the CSP allows, which defaults to the `VITE_API_URL` build arg. Override it with
  `docker run -e CSP_CONNECT_SRC=https://api.example.gov.pl` when the API moves; empty = same origin only.

Build and run the image locally:

```bash
docker build --build-arg VITE_API_URL=http://localhost:3000 -t hacknation-frontend .
# add --build-arg VITE_DEMO_ACCOUNTS=false to build without the demo accounts
docker run --rm -p 8080:80 hacknation-frontend   # http://localhost:8080
```
